# Step 9: Obstacle (knocked-over cones) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The module writes `obstacle` for a knocked-over cone on every lap on which it is seen, and has one clear place where later kinds of event are added.

**Architecture:** A ready-made model that takes words (OWLv2 from the `transformers` library) finds cones in the reduced pictures, in its own pass over the video at its own picture rate. Its boxes are saved per video in `name-objects.json`. A rule on the saved boxes reports a cone whose box is clearly wider than tall. The words to look for (`settings.OBJECT_WORDS`) and the list of rules (`object_events.OBJECT_RULES`) are the place for later kinds.

**Tech Stack:** Python 3.13 in `.venv`, `unittest`, PyTorch (installed), `transformers` 5.23.0 (installed for the trial with the author's yes), Pillow (installed).

**Spec:** `docs/superpowers/specs/2026-11-16-obstacle-design.md`

## Global Constraints

- Run the checks with `.venv\Scripts\python.exe -W error::ResourceWarning -m unittest`.
- The author runs Git. Each task ends by giving the `git add` and `git commit` commands with a line on what each does; never commit or push.
- Stop after each task and wait for the author's go-ahead. **No module code is written before the author has judged the count of Task O0.**
- The values below are the trial's. `OBJECT_FRAMES_PER_SECOND`, `OBJECT_BATCH_SIZE` and the `OBSTACLE_` values are fixed by Task O0; where O0 changes one, the checks of the later tasks use the new value.
- Rules read `settings.NAME` at the moment they run; never copy a setting into a default argument or with `from pp_tt_video.settings import NAME`.
- `transformers` and `torch` are imported inside `ObjectDetector.__init__` only. No check may need the model, except checks that are skipped when the libraries or the example video are missing.
- `name-detections.json` and `pp_tt_video/detections_file.py` do not change.
- No GPS, no laps.
- First values: `OBJECT_MODEL = "google/owlv2-base-patch16-ensemble"`, `OBJECT_WORDS = {"cone": "a traffic cone"}`, `OBJECT_FRAMES_PER_SECOND = 2`, `OBJECT_MIN_CONFIDENCE = 0.15`, `OBJECT_BATCH_SIZE = 4`, `OBSTACLE_MIN_CONFIDENCE = 0.30`, `OBSTACLE_MIN_WIDTH_RATIO = 1.5`, `OBSTACLE_MIN_WIDTH_FRACTION = 10 / 1280`, `OBSTACLE_MERGE_SECONDS = 3`, `OBSTACLE_TAIL_SECONDS = 2`.
- When trying things on the examples, always give `--output-folder` a scratch folder. Running on the five videos in `input video files/` needs the author's yes each time (slow).
- Do not change the hand-made events files.
- Nothing is installed without asking.
- Code readable for someone new to Python: plain names, comments that say why.
- The repository is public: no absolute paths from this PC, no personal data.

## Review Focus

1. **A saved objects file made with other words, another model, picture size, rate or lowest score:** must not be reused; the search runs again. Test in O1 (`fits_settings`).
2. **A half-written or damaged objects file:** refused with `ObjectsError`, then replaced by a new search; never a crash. Test in O1 and O2.
3. **A box with height 0, or a picture with no boxes at all:** the rule must not divide by zero and reports nothing. Test in O2.
4. **A cone sighting outside the part at pace (paddock, pit lane):** no `obstacle` line. Test in O2.
5. **A PC without `transformers`:** `--gps-only` still works, and a normal run reports "detection libraries are not installed" for the events of that video instead of stopping. Test in O2.

- Produces, in `objects_file.py`:

  - `Objects(analysis_width, picture_height, frames_per_second, min_confidence, model: str, words: dict, pictures: list)`; `pictures` is one `(time in seconds, [ObjectBox, ...])` per searched picture.

- Produces, in `find_objects.py`:
  - `ObjectDetector(use_graphics_card=None)` with `detect(frames) -> list of [ObjectBox]`, one list per frame.
  - `find_objects(video_path, detector, on_progress=None) -> Objects`.
  - `main()`: the command `python -m pp_tt_video.find_objects "<video or folder>" [--output-folder F] [--overwrite]`, which writes the objects file of every video and prints one line per video (name, pictures, boxes, seconds).
